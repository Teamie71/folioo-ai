# 에이전트

- 목차

## 1. 개요

### 1.1. 목적

- **경험정리 AI 에이전트 정의**
    - 취준생이 자신의 경험을 정리하는 과정을 보조하는 에이전트
    - 사용자가 자신의 경험을 떠올리고, 정리하고, 실제 취업 준비에 활용하는 과정에서 느끼는 부담을 줄이는 것을 지향
- **v.3 목적**
    - 사용자가 제공한 정보를 정해진 경험정리 블록 구조에 맞게 정리하는 목적으로 한정

### 1.2. 기능 및 구조

- 사용자 입력을 Router에서 판정한 뒤, 분기하여 처리
1. **파일 업로드 시 블록으로 정리**
    - 사용자가 업로드한 파일에서 경험정리에 활용 가능한 내용을 식별하여 적절한 경험정리 블록으로 반영
    - Router → 파일처리
2. **채팅에 내용 입력 시 블록으로 정리**
    - 사용자가 채팅으로 입력한 내용에서 경험 정리에 활용 가능한 내용을 식별하여 적절한 경험정리 블록으로 반영
    - 이미 만들어진 블록에 내용을 추가하여 수정하지 않고, 주어진 내용을 새로운 블록으로 정리
    - Router → 블록 반영 내용 필터링 → 구조화
3. **제안된 gap을 해소하여 블록에 반영**
    - 에이전트가 앞서 제안한 gap을 해소하기 위해 사용자가 정보를 제공하면, 이를 경험정리 블록으로 반영
    - gap 정보에 따라 구조화부터 다시 진행하거나, 이미 만들어진 블록에 내용을 추가하여 수정
    - Router → 블록 반영 내용 필터링 → 구조화 또는 문장 정제
4. **Fallback**
    - 사용자의 요청이 에이전트 기능 범위를 벗어난 경우, fallback 응답으로 처리
    - Router → Fallback

## 2. 경험정리 체계

### 2.1. 경험정리의 정의

- 사용자의 경험을 취업 준비에 활용할 수 있도록 정해진 위계와 블록 단위로 구조화하는 방식

### 2.2. 좋은 경험정리의 특징

1. **구체적인 기록**
    - 추상적인 표현이 아닌, 실제 행동과 맥락, 사고 과정이 구체적으로 드러나도록 정리
    - 표면적으로 드러나는 행동과 결정 (What), 구체적인 수행 방식 (How), 행동을 한 이유 (Why)가 모두 포함될 것
    - 최대한의 구체성을 확보
    - 포함할 항목 예시
        - 어떤 방식으로 조사했는가?
        - 어떤 기준으로 판단했는가?
        - 그 문제를 해결해야 했던 이유는 무엇인가?
        - 어떤 결과가 나타났는가?
2. **수치 포함**
    - 경험의 내용과 결과를 구체적으로 보여주는 숫자 정보를 포함하여 정리
    - 포함할 항목 예시
        - 증가율, 달성률, 전환율, 참여자 수 등 정량적인 성과
        - 목표 대비 실제 결과의 차이
        - 실행 전후의 변화 폭
        - 기간, 횟수 등 행동의 진정성이 드러나는 증거
3. **배운 점과 활용 방향 포함**
    - 이 활동/담당업무/문제해결을 통해 성장한 부분이 보이도록 정리
    - 포함할 항목 예시
        - 아쉬웠던 점과 개선 방향
        - 이후 유사한 상황에서 적용할 방식
        - 이전보다 나아진 역량이나 관점
        - 얻은 인사이트

### 2.3. 블록의 정의

- 경험정리를 구성하는 최소 정보 단위
- 사용자의 경험은 하나의 긴 글로 저장되지 않고, 목적이 구분된 여러 블록으로 구조화되어 저장
- 각 블록은 정해진 위계와 목적을 가지며, 일부 블록은 템플릿 사용 가능

### 2.4. 블록의 위계 정의

- 반드시 참고: [경험정리 템플릿](https://app.notion.com/p/38f157eb55e280558721f316935e904f?pvs=21)

#### 2.4.1. 1단계 블록: 그룹

- 여러 활동을 묶는 최상위 단위
- 사용자의 활동을 시기, 활동 유형, 주제 등에 따라 구분하기 위해 사용
- AI 에이전트는 1단계 블록의 생성, 삭제, 수정 불가

#### 2.4.2. 2단계 블록: 활동

- 사용자가 실제로 수행한 하나의 활동 단위
- 하나의 활동은 공통된 맥락과 목표를 공유
- AI 에이전트는 2단계 블록의 생성, 삭제, 수정 불가

#### 2.4.3. 3단계 블록: 카테고리

- 하나의 활동을 목적에 따라 구분해 정리하는 단위
- AI 에이전트는 3단계 블록의 삭제와 수정 불가, 생성 가능
    - 사용자 입력 중 기본 제공 카테고리에 정리하기 적합하지 않은 내용이 있다면, 새로운 카테고리를 생성하여 해당 내용 반영
    - 기본 제공 카테고리 중 누락된 블록이 있다면, 필요에 따라 해당 카테고리를 새로 생성
- 기본 제공 카테고리는 아래 5가지


    | 카테고리 | 카테고리 목적 | 4단계 블록에 포함하는 내용 | 5단계 블록에 포함하는 내용 |
    | --- | --- | --- | --- |
    | 상세정보 | 활동의 기본 맥락과 배경 정리 | 시작한 배경과 달성하고자 한 목표 | 각 4단계 블록의 구체적인 하위 내용이 존재하는 경우 |
    |  |  | 전체 진행 기간 |  |
    |  |  | 본인의 역할과 전체 인원의 역할 분담 |  |
    |  |  | 주요 타깃, 사용자, 혹은 고객 |  |
    |  |  | 본인이 직접 활용한 기술, 방법론, 혹은 툴 |  |
    | 주요성과 | 활동을 통해 만들어낸 결과 정리 | 수치로 증명할 수 있는 정량적인 성과 | 각 4단계 블록의 구체적인 하위 내용이 존재하는 경우 |
    |  |  | 간접적인 지표로 확인할 수 있는 정성적인 성과 |  |
    | 담당업무 | 사용자가 직접 맡은 업무와 실행 방식 정리 | 담당한 주요 업무 또는 역할 | 템플릿을 사용하여 해당 담당업무 에피소드의 내용 구체화 |
    | 문제해결 | 발생한 문제와 해결 과정 정리 | 문제해결 에피소드를 한 줄로 요약 | 적절한 템플릿을 사용하여 해당 문제해결 에피소드의 내용 구체와 |
    | 배운 점 | 활동을 통해 얻은 학습과 성장 내용 정리 | 새롭게 배우거나 성장한 점, 향후 활용 계획 | 각 4단계 블록의 구체적인 하위 내용이 존재하는 경우 |

#### 2.4.4. 4단계 블록: 항목

- 3단계 카테고리를 구성하는 하위 단위
- AI 에이전트는 4단계 블록의 삭제 불가, 생성과 수정 가능

#### 2.4.5. 5단계 블록: 세부 항목

- 4단계 항목을 더 구체적으로 나누어 정리하기 위한 하위 단위
    - 담당업무와 문제해결 카테고리 하에서는 템플릿을 사용하여 구체적으로 정리하는 것을 권장
    - 그 외 카테고리 하에서는 필요한 경우에만 생성하여 사용
- AI 에이전트는 5단계 블록의 삭제 불가, 생성과 수정 가능

## 3. 노드 구성

- **공통 규칙**: 제공되지 않은 정보 생성 금지
- **실패 시 재시도 정책**
    - 노드마다 1회
    - gap 분석 노드는 실패 시에도 재시도하지 않고, 화면에 표시하지 않음
    - 유저가 재시도 버튼 클릭 시, 실패한 노드부터 재실행

### 3.1. Router

- **Goal**
    - 사용자 입력의 의도를 파악하여, 적절한 노드로 분기
- **Input**
    - 사용자 입력
    - 파일 업로드 여부
- **분기 대상 노드와 기준**
    - [1.2. 기능 및 구조](https://app.notion.com/p/1-2-3ae157eb55e28067a112f63210b786c5?pvs=21) 참고
    1. 파일처리
        - 사용자가 파일을 업로드한 경우
    2. 블록 반영 내용 필터링
        - 사용자가 채팅으로 경험정리에 반영할 수 있는 내용을 입력한 경우
        - 사용자가 채팅으로 내용을 입력하고, 경험정리 반영을 요청한 경우
            - e.g. “넣어줘”/ “반영해줘”/ “정리해줘”
    3. Fallback
        - 사용자의 요청이 에이전트 기능 범위를 벗어난 경우
            - 경험정리, 취업 준비와 무관한 입력
            - 자기소개서, 포트폴리오, 면접 질문 생성 등 실제 지원 과정 보조 요청
            - 정리된 경험과 관련된 질문 또는 품질 판단 요청
            - 내용을 제공하지 않은 상태로 블록의 단순 생성 또는 수정 요청
            - 블록 이동 또는 삭제 요청
            - 그 외 v.3에서 준비한 기능 밖의 모든 요청
        - Fallback 노드로의 분기는 보수적으로 접근하며, 사용자의 입력이 블록에 반영될 여지가 조금이라도 존재하는 경우 블록 반영 내용 필터링으로 분기
- **Output**
    - 후속 처리 노드

### 3.2. 파일처리

- **Goal**
    - 업로드한 파일의 텍스트를 추출
- **Input**
    - 업로드한 파일
- **처리 방식**
    - 파일 형식에 따라 1과 2 중 처리 방식 결정
    1. 파일 파서 사용
        - TXT, DOCX, PPTX
    2. OCR 모델 사용
        - PDF는 텍스트 레이어 유무와 관계없이 모든 페이지를 이미지로 렌더링한 뒤 페이지별 OCR
        - PNG, JPG/JPEG
        - 한 PDF의 여러 페이지를 하나의 모델 요청에 몰아넣지 않음
- **후속 처리 기준**
    - 파일의 텍스트 추출이 성공한 경우 블록 반영 내용 필터링 노드로 전달
    - 파일의 상태나 품질 문제로 텍스트 추출이 불가능한 경우 Fallback 노드로 전달
- **Output**
    - 후속 처리 노드
    - 추출한 텍스트

### 3.3. 블록 반영 내용 필터링

- **Goal**
    - 사용자가 입력/업로드한 텍스트의 내용을 확인하고, 전체 내용을 아래 세 가지로 분류
        - 활성 gap 답변 내용
        - 경험정리 블록에 새로 반영할 수 있는 내용
        - 반영 제외 내용
- **Input**
    - 사용자 입력
    - (존재 시) 파일 추출 텍스트
    - 활성 gap 존재 여부
    - (존재 시) 활성 gap 내용
    - (존재 시) 활성 gap 다음 처리 노드
- **Tool**
    - 경험정리 내용 조회 API
        - 범위: 해당 활동에 저장된 2-5단계의 모든 블록 내용 조회
        - 목적: 사용자 입력과 파일 추출 텍스트를 기존 경험정리 내용과 비교
        - 사용자 요청 수행을 위해 Tool 사용 목적 달성이 필요한 경우 사용
            - e.g. “이미 있는 내용은 제외하고 추가해”
            - e.g. “현재 활동에 해당하는 내용만 골라서 추가해”
- **필터링 기준**
    1. 활성 gap 답변 내용
        - 활성 gap이 존재하고, 이를 해소하기 위한 내용인 경우
            - e.g. gap 질문에서 요청한 정보를 제공한 경우
            - e.g. gap에서 부족하다고 지적한 정보를 제공한 경우
    2. 새로 반영할 내용
        - 사용자가 수행한 경험의 맥락, 과정, 결과, 학습 등을 설명하여 현재 활동에 반영할 수 있는 정보인 경우
        - 사용자가 반영을 요청한 내용이 있다면, 반드시 새로 반영할 내용으로 분류
    3. 반영 제외 내용
        - 사용자의 경험정리에 반영할 수 없는 내용
            - e.g. 사용자가 수행하거나 겪지 않은 경험
            - e.g. 사용자의 경험이 아닌, 일반 지식의 나열
            - e.g. 경험정리 또는 취업준비와 무관한 내용
        - 사용자가 반영 제외를 요청한 내용
            - e.g. “인스타그램 운영 업무는 제외하고 정리해줘”
            - e.g. “이미 정리된 내용은 제외하고 정리해줘”
        - 사용자가 제공한 정보 외의 요구사항 텍스트
            - e.g. “이 문서의 내용을 정리해줘”
        - 파일의 문서 제목·구획 제목
            - e.g. “담당 업무”, “상황”, “원인 분석”, “해결 과정”, “결과”
            - 단, 구체적인 에피소드 요약이 함께 있는 제목은 요약 내용으로 반영 가능
- **후속 처리 기준**
    - 반영 제외 내용은 모두 폐기
    - gap 답변 내용만 존재 → 해당 gap에 정해진 후속 노드로 전달
    - 새로 반영할 내용만 존재 → 블록 단위 구조화 노드로 전달
    - 구조화가 필요한 gap 답변과 새로 반영할 내용이 모두 존재 → 모두 블록 단위 구조화 노드로 전달
    - 문장 정제가 필요한 gap 답변과 새로 반영할 내용이 모두 존재
    → 새로 반영할 내용을 블록 단위 구조화 노드로 전달
    → 구조화 결과와 gap 답변 내용을 함께 문장 정제 노드로 전달
    - 반영 제외 내용만 존재 → Fallback 노드로 전달
- **Output**
    - 후속 처리 노드
    - (존재 시) 활성 gap 답변 내용 텍스트
    - (존재 시) 새로 반영할 내용 텍스트

### 3.4. 블록 단위 구조화

- **Goal**
    - 텍스트의 수정 없이 경험정리 체계에 맞게 구조화
    - [2.4. 블록의 위계 정의](https://app.notion.com/p/2-4-3ae157eb55e28010b9c7e52177be31fc?pvs=21) 에 명시된 정책에 따라 블록 생성 또는 수정 가능
- **Input**
    - (존재 시) 새로 반영할 내용 텍스트
    - (존재 시) 활성 gap 답변 내용 텍스트
    - (존재 시) 활성 gap 기준 블록 ID
- **구조화 기준**
    - 활성 gap 답변 내용 텍스트는 반영 위치 정보를 기준으로 구조화
        - 활성 gap 기준 블록 ID 아래에 생성할 하위 블록으로 구조화
    - 새로 반영할 내용 텍스트는 신규 블록 생성 대상으로 구조화
        - 적절한 3단계 카테고리 판단 → 생성할 4단계 항목 판단 → 필요한 경우 생성할 5단계 세부 항목 판단
    - 파일의 원문을 여러 배치로 나눠 구조화해도 각 원문의 문서 내 위치를 유지
        - 인접한 앞쪽 구획 제목을 기준으로 3·4·5단계 슬롯을 판단
        - e.g. “해결 과정” 아래 원문은 문제해결의 해결책 슬롯, “배운 점” 아래 원문은 배운 점 카테고리로 구조화
- **처리 기준**
    - 입력 내용의 구체성을 반드시 유지
    - 전달된 텍스트를 수정하지 않고 블록 단위로 분류
    - 기존에 존재하는 블록을 수정하지 않음
    - 전달된 새 내용과 구조화가 필요한 gap 답변은 누락·중복 없이 각각 정확히 한 번만 구조화 결과에 포함
        - 누락되거나 여러 블록에 중복 배정된 원문이 있으면, 해당 원문과 같은 블록에 함께 배정되어 영향을 받은 원문만 대상으로 1회 보정
        - 보정 시 이미 정상적으로 구조화된 원문과 블록 위계는 유지
        - 보정 후에도 누락·중복이 남으면 일부 내용만 저장하지 않고 블록 단위 구조화 노드 실패로 처리
- **Output**
    - 구조화 결과
- **후속 처리 노드**
    - 문장 정제 노드

### 3.5. 문장 정제

- **Goal**
    - 구조화 결과를 실제 블록에 저장할 문장으로 정제
    - 원문의 의미와 구체성을 최대한 유지하면서, 취업 준비에 활용하기 좋은 표현을 사용한 자연스러운 문장으로 정제
- **Input**
    - (존재 시) 구조화 결과
    - (존재 시) 활성 gap 답변 내용 텍스트
    - (존재 시) 활성 gap 기준 블록 ID
- **처리 기준**
    - Input 유형에 따라 아래와 같이 구분하여 처리
    - 두 유형이 모두 전달된 경우, 각각 구분하여 처리
    1. 활성 gap 답변 내용 텍스트
        - 활성 gap 기준 블록 ID 내의 기존 텍스트와 활성 gap 답변 내용 텍스트를 결합하여 문장 정제
    2. 구조화 결과
        - 블록 정보와 원문 텍스트이 매핑을 유지한 채, 원문 텍스트 정제
- **정제 기준**
    - 구조화 결과 텍스트의 사실과 의미를 유지
    - 텍스트에 없는 내용의 임의 생성은 절대 금지
    - 추상적인 표현보다 구체적인 행동, 맥락, 사고 과정이 드러나도록 정제
    - 표면적인 행동뿐 아니라 가능한 범위에서 아래 정보가 드러나도록 문장 구성
        - What: 무엇을 했는지
        - How: 어떤 방식으로 수행했는지
        - Why: 왜 그렇게 판단하거나 행동했는지
        - Result: 어떤 결과와 배운 점이 있었는지
    - 가능한 범위에서 [2.2. 좋은 경험정리의 특징](https://app.notion.com/p/2-2-3ae157eb55e280278ff5c8b887cde18a?pvs=21) 을 만족하도록 작성
    - 명사종결로 작성
    - 화살표 (→), 슬래시 (/) 등을 활용하여 구조적으로 작성
- **Output**
    - 블록별 정제 결과
- **후속 처리 노드**
    - Validation 노드

### 3.6. Validation

    - 각 블록 내의 글자수는 500자를 초과하지 않을 것
- **조건 중 하나라도 준수되지 않은 경우 아래와 같이 처리**
    - AI 에이전트 업무 범위 또는 위계 조건 미준수 → 블록 단위 구조화 노드로 회귀
    - 글자수 조건 미준수 → 문장 정제 노드로 회귀
- **통과 시 DB Commit 노드와 gap 분석 노드를 병렬로 실행**

- **Commit 직전에 스냅샷을 찍어 저장**

### 3.8. 결과 응답 출력

- 아래 템플릿에 변수만 달리하여 출력

    ```markdown
    내용을 분석하여 경험을 정리했어요.
    - {카테고리명} 아래 {N}개의 블록 수정
    - {카테고리명} 아래 {N}개의 블록 생성
    - {카테고리명} 생성
    ```

    - 첫 문장은 고정으로 출력
    - 불렛포인트는 변경이 발생한 3단계 카테고리 단위로 출력
        - 수정한 블록 수가 0개인 경우 ‘{카테고리명} 아래 {N}개의 블록 수정’은 출력하지 않음
        - 생성한 블록 수가 0개인 경우 ‘{카테고리명} 아래 {N}개의 블록 생성’은 출력하지 않음
        - ‘{카테고리명} 생성’은 3단계 블록을 생성한 경우에만 출력
    - {카테고리명} 내에는 수정 또는 생성한 블록이 속한 3단계 블록 내의 텍스트 표시
    - 같은 카테고리 내에서 블록 수정과 생성이 모두 발생한 경우, 각각 별도 불렛포인트로 출력
    - 여러 카테고리에서 수정과 생성이 발생한 경우, 카테고리별 변경 내역을 각각 불렛포인트로 출력


### 3.9. gap 분석

- **Goal**
    - 이번 턴에서 DB에 commit된 내용을 기준으로 보완이 필요한 gap을 분석하고, 우선순위에 따라 사용자에게 최대 1개의 제안 출력
    - [2.2. 좋은 경험정리의 특징](https://app.notion.com/p/2-2-3ae157eb55e280278ff5c8b887cde18a?pvs=21) 과 비교했을 때 부족한 정보 확인
- **gap 분석 및 우선순위**
    - 이번 턴에서 새로 commit된 경험정리 내용을 기준으로 gap 분석 및 우선순위 적용
    - 한 번의 응답에서 생성할 수 있는 gap은 최대 1개, 가장 우선순위가 높은 gap을 출력
    - 1순위: 해당 카테고리의 핵심 정보 누락
        - 이번에 추가/수정된 블록의 핵심 목적을 이해하는 데 필요한 정보가 빠진 경우
        - 해당 블록이 무엇에 대한 내용인지 불분명하면 가장 먼저 gap으로 생성
        - e.g.
            - 담당업무의 하위 블록인데 실제 담당한 업무가 불분명한 경우
            - 문제해결의 하위 블록인데 해결한 문제가 불분명한 경우
            - 주요성과의 하위 블록인데 무엇의 성과인지 불분명한 경우
            - 배운 점의 하위 블록인데 무엇을 통해 배웠는지 불분명한 경우
    - 2순위: 사용자의 직접적인 행동 부족
        - 이번 commit 내용에 사용자가 실제로 한 행동이 부족한 경우
        - 경험정리에서 자기소개서/면접에 활용되려면 사용자의 기여가 드러나야 하므로 우선 보완
        - e.g.
            - “프로젝트를 진행했다”처럼 사용자의 역할이 드러나지 않는 경우
            - “문제를 해결했다”처럼 실제 행동이 빠진 경우
            - “분석했다”라고만 되어 있고 어떤 분석을 했는지 없는 경우
    - 3순위: 수행한 방식 또는 판단의 기준 부족
        - 사용자가 한 일은 있으나 어떻게 했는지, 왜 그렇게 했는지가 부족한 경우
        - 단순 활동 기록을 역량이 드러나는 경험으로 바꾸기 위해 보완
        - e.g.
            - 어떤 기준으로 판단했는지 부족한 경우
            - 어떤 방식으로 조사/분석/실행했는지 부족한 경우
            - 특정 방법을 선택한 이유가 부족한 경우
    - 4순위: 배운 점 또는 활용 방향 부족
        - 경험을 통해 사용자가 배운 점이나 얻은 인사이트, 활용 방향이 부족한 경우
        - e.g.
            - 이 경험을 통해 얻은 인사이트가 부족한 경우
            - 아쉬웠던 점이나 개선 방향이 부족한 경우
            - 이후 유사한 상황에서 어떻게 활용할지 부족한 경우
    - 5순위: 결과 또는 변화 부족
        - 행동이나 과정은 있으나 그 결과가 부족한 경우
        - 가능하면 수치 정보를 우선 확인하고, 없으면 정성적 변화나 피드백을 확인
        - e.g.
            - 실행 후 어떤 변화가 있었는지 부족한 경우
            - 성과를 보여주는 수치가 부족한 경우
            - 사용자/팀/외부 반응이 부족한 경우
    - 같은 우선순위의 gap이 여러 개라면 아래 기준으로 선택
        - 이번 commit 내용과 가장 직접적으로 연결되는 gap
        - 사용자가 한 번의 답변으로 쉽게 보완할 수 있는 gap
        - 보완했을 때 해당 블록의 활용도가 가장 크게 올라가는 gap
    - 아래 경우에는 gap 생성하지 않음
        - 이번 commit 내용만으로 충분히 구체적인 경우
        - 이번 commit 내용과 직접 관련 없는 경우
        - 사용자가 답변해도 해당 블록의 품질 개선 효과가 낮은 경우
        - 전체 경험 맥락을 봐야만 판단할 수 있는 경우
- **gap 유형**
    1. 기존 블록 보완
        - 이미 존재하는 블록에 답변 내용을 추가하면 되는 경우
        - gap 생성 시 기존 블록 ID 기록
        - 사용자가 답변하면 문장 정제 노드로 전달
    2. 신규 하위 블록 생성
        - 답변 내용을 별도 하위 블록으로 생성해야 하는 경우
        - gap 생성 시 기준 블록 ID 기록
        - 사용자가 답변하면 블록 단위 구조화 노드로 전달
        - 생성 위치는 기준 블록의 하위로 고정
- **사용자에게 출력할 제안 생성**
    - 사용자에게 보여줄 제안은 한 문장으로 생성
    - 부족한 정보를 직접적으로 묻는 문장으로 작성
    - 부담을 주는 평가 표현 지양
    - 사용자가 바로 답변할 수 있도록 구체적으로 질문
    - gap이 없는 경우
        - 이번 턴 commit 결과가 좋은 경험정리의 기준에 부합한다고 판단되면 gap 생성하지 않음
    - gap이 없거나 제안 생성에 실패한 경우, 정해진 문구 출력 “더 정리하고 싶으신 내용이 있나요?”
- **Output**
    - 사용자에게 출력할 제안
    - (존재 시) 생성한 gap
    - (존재 시) gap 유형
    - (존재 시) 기준 블록 ID

### 3.10. Fallback

- **Goal**
    - 사용자의 요청이 에이전트의 기능 범위를 벗어난 경우, 기능 범위를 안내하고 사용자가 다시 경험정리에 활용 가능한 입력을 제공하도록 유도
- **Input**
    - 사용자 입력
    - 선행 노드
- **Fallback 처리 대상**
    1. 경험정리, 취업 준비와 무관한 입력
    2. 자기소개서 작성, 포트폴리오 첨삭, 면접 질문 생성, 직무 추천 등 에이전트 기능 범위를 벗어난 취업 준비 요청
    3. 정리된 경험에 대한 질문, 평가, 품질 판단 요청
    4. 내용을 제공하지 않은 상태의 블록 생성/수정 요청
    5. 블록 이동 또는 삭제 요청
    6. 파일 상태나 품질 문제로 텍스트 추출이 불가능한 경우
    7. 블록 반영 내용 필터링 결과, 경험정리 블록에 반영할 수 있는 내용이 없는 경우
    8. 그 외 현재 경험정리 블록 반영 기능으로 처리할 수 없는 요청
- **응답 기준**
    - 사용자가 요청한 작업을 현재 수행할 수 없음을 짧게 안내
    - 현재 AI 에이전트가 할 수 있는 범위를 함께 안내
        - 사용자가 입력한 경험 내용을 블록으로 정리
        - 업로드한 파일에서 경험정리에 활용 가능한 내용 추출
        - 부족한 정보에 대한 답변을 기존 블록 또는 하위 블록에 반영
    - 사용자가 다음 행동을 쉽게 알 수 있도록 구체적인 재입력 방식을 제안
    - 평가하거나 꾸짖는 표현을 사용하지 않음
    - 내부 노드명, 실패 사유, 시스템 판단 기준을 그대로 노출하지 않음
- **금지사항**
    - 기능 밖 요청을 수행한 것처럼 응답하지 않음
    - DB 수정, 블록 생성, 블록 수정, 블록 삭제를 수행하지 않음
    - gap을 새로 생성하지 않음
    - 파일처리 실패 시 OCR 결과를 추측하지 않음
    - 자기소개서 문항 답변, 포트폴리오 첨삭 결과, 면접 답변을 생성하지 않음
- **Output**
    - 사용자에게 출력할 fallback 응답
- **응답 템플릿**
    1. 선행 노드가 Router인 경우

        ```markdown
        지금은 제공해주신 내용을 바탕으로 경험을 정리하는 것만 도와드릴 수 있어요.
        정리하고 싶은 경험의 상황, 맡은 역할, 진행 과정, 결과를 알려주시면 적절한 블록으로 정리해드릴게요.
        ```

    2. 선행 노드가 블록 반영 내용 필터링인 경우

        ```markdown
        경험정리 블록에 반영할 수 있는 내용을 찾지 못했어요.
        어떤 활동에서 무엇을 했고, 어떤 방식으로 진행했으며, 결과가 어땠는지 알려주시면 블록으로 정리해드릴게요.
        ```
