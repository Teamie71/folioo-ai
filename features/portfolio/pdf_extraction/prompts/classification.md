# PDF 활동 구조화 기준

다음 기준에 따라 PDF 내용을 `PdfExtractionResult` 스키마로 구조화한다.

## 활동 추출 범위
- `activities`에는 PDF에서 확인 가능한 주요 활동만 포함한다.
- 활동별 필수 구조화 대상 필드는 `activity_name`, `detail`, `responsibility`, `problem_solving`, `learning`이다.
- 활동은 최대 5개까지만 추출한다.
- 같은 활동을 제목만 바꿔 반복하거나, 사실상 동일한 내용을 분리해 중복 생성하지 않는다.

## 활동 분리 기준
- 프로젝트, 인턴, 동아리, 연구, 대외활동처럼 맥락과 책임이 독립적인 단위를 하나의 활동으로 본다.
- 하나의 활동 안에서 여러 업무가 있었다면 `detail`과 `responsibility` 안에서 통합 정리한다.
- 활동 구분이 불명확하면 과도하게 쪼개지 말고 더 큰 맥락의 활동 하나로 묶는다.

## 필드 작성 기준
- `activity_name`: 활동을 식별할 수 있는 고유 명칭으로 작성한다.
- `detail`: 활동의 목적, 맥락, 기간, 결과물 등 핵심 설명을 사실 기반으로 요약한다.
- `responsibility`: 지원자가 실제로 맡은 역할과 수행 업무를 구체적으로 정리한다.
- `problem_solving`: 문제 해결 경험이 명확할 때만 포함한다.
- `learning`: 활동을 통해 얻은 역량, 인사이트, 개선 관점을 정리한다.

## 중복 제거 기준
- 동일한 프로젝트명, 동일 기간, 동일 결과물, 동일 책임 범위를 가리키면 하나의 활동으로 병합한다.
- `detail`, `responsibility`, `learning`에 중복 문장이 생기지 않도록 합쳐서 정리한다.
- 문제 해결 사례도 동일 상황/전략/근거를 반복하지 않는다.

## problem_solving.no 규칙
- 각 활동의 `problem_solving` 목록에서 `no`는 1부터 시작한다.
- 같은 활동 안에서는 1, 2, 3 ... 순으로 오름차순을 유지한다.
- 번호는 건너뛰지 않는다.
- 새 활동이 시작되면 다시 1부터 번호를 매긴다.

## 금지 사항
- PDF에 없는 사실을 추정해 채우지 않는다.
- 빈 값을 억지로 생성하지 않는다.
- 활동 수를 맞추기 위해 중요하지 않은 항목을 억지로 추가하지 않는다.
